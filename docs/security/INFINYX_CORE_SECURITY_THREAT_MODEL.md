## 1. هدف

شناسایی دارایی‌های حیاتی، مرزهای اعتماد، عوامل تهدید، مسیرهای حمله و کنترل‌های امنیتی موردنیاز برای محافظت از هسته INFINYX.

این سند یک مدل تهدید پیشنهادی است و اثبات امنیت پیاده‌سازی فعلی محسوب نمی‌شود.

## 3. عوامل تهدید

- مهاجم خارجی با دسترسی شبکه‌ای
- ماژول مخرب یا آسیب‌پذیر
- عامل هوشمند دارای مجوز بیش از حد
- ارزیاب Policy غیرهمکار یا معیوب
- فرایند فرزند خارج از کنترل
- وابستگی نرم‌افزاری آلوده
- کاربر داخلی با دسترسی نامناسب
- خطای پیکربندی یا عملیات مدیریتی

## 4. مرزهای اعتماد

1. External Input → Core API
2. Core Platform → Security Layer
3. Security Layer → Policy Evaluator
4. Core Engine → Runtime Process
5. Parent Process → Child Process
6. Module → Event Bus
7. Runtime → External Tool
8. Application → Persistent Storage

هر عبور از مرز اعتماد باید دارای قرارداد اعتبارسنجی، احراز هویت، مجوزدهی و ثبت رویداد متناسب با ریسک باشد.

## 6. کنترل‌های امنیتی الزامی

### Authorization

- Fail-Closed
- Least Privilege
- مجوزهای محدود به عملیات و منابع
- عدم اعتماد به Metadata درخواست‌کننده

### Runtime

- جداسازی واقعی فرایند
- محدودیت CPU و حافظه
- کنترل Process Tree
- محدودیت فایل‌سیستم و شبکه
- توقف قابل اثبات

### Lifecycle

- اعتبارسنجی متمرکز انتقال وضعیت
- نتیجه نهایی تغییرناپذیر
- تفکیک Termination، Cleanup و External Effects
- ثبت وضعیت UNRESOLVED در صورت نبود شواهد کافی

### IPC

- اعتبارسنجی Schema
- سقف اندازه پیام
- محدودیت نرخ درخواست
- کنترل هویت فرستنده
- جلوگیری از Replay در عملیات حساس

### Audit

- ثبت تصمیم‌های امنیتی
- ثبت شناسه درخواست و عملیات
- جلوگیری از ثبت Secret
- حفاظت در برابر تغییر یا حذف غیرمجاز سوابق

## 8. معیار پذیرش مدل تهدید

- تمام دارایی‌های حیاتی مالک و سطح دسترسی مشخص داشته باشند.
- تمام مرزهای اعتماد مستند باشند.
- تهدیدهای P0 دارای کنترل و آزمون قابل تکرار باشند.
- آزمون‌های سوءاستفاده و نفوذ متناسب با معماری اجرا شوند.
- یافته‌های حل‌نشده صریحاً گزارش شوند.
- بازبین مستقل، پوشش مدل تهدید را ارزیابی کند.
